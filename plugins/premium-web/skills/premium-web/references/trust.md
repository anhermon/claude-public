# Trust devices and lead capture (no dark patterns)

- **Proof inventory first** (intake): list what is real and checkable: repos, releases, licences, dated stars,
  public talks, named clients who agreed to be named. The page may only use items on that list.
- **Never fabricate**: no invented stats, testimonials, logos, user counts, benchmarks or press. Sample data is
  labelled "sample data" where it appears. "Illustrative" captions on visuals that are not measurements
  (anhermon: "Strands drawn from an illustrative 8-span run, not a customer trace").
- **Unverified claims are fabricated claims**: the v3 "general knowledge" exemplar claims were cut because nobody
  could check them. Every number has a source and a date next to it.
- **Limits stated plainly** are a trust device: a "what it does not do" section, or a Limit callout per proof item
  quoting the README (anhermon proof cards).
- **Who replies**: a real name and how fast, "replies personally" only if true.
- **Lead capture**: one primary action repeated (hero, after proof, footer). No exit-intent popups, no fake
  scarcity or countdowns, no pre-ticked boxes, no confirmshaming ("No, I don't want to grow"), no forced account.
- Analytics: say so in the privacy line (e.g. masked session replays). Tests never send events to real analytics:
  serve.mjs stubs trackers and chrome-shot blocks them.
- Concepts for fictional products carry a small "Concept project, fictional product" line in the footer.
